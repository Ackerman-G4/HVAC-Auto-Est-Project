# cfd-solver

Engineering-tier OpenFOAM 2406 batch worker for the HVAC Auto-Estimation System
(plan v2.0 §4). Reads a case package generated by the TypeScript
`openfoam-exporter`, runs `blockMesh → topoSet → createPatch → <solver>`,
extracts fields with `fluidfoam`, and reports back to the app.

## Contract

Input (`CASE_INPUT_PATH`, JSON) — produced by `POST .../simulations/[simId]/runs`:

```jsonc
{
  "solver": "buoyantSimpleFoam",
  "caseName": "room-123",
  "files": { "system/controlDict": "…", "0/T": "…", "constant/…": "…" },
  "dimensions": { "nx": 40, "ny": 24, "nz": 20 },
  "runJobId": "…",
  "callbackUrl": "https://app/api/…/openfoam-callback",
  "callbackSecret": "…"
}
```

Output — POSTed to `callbackUrl` with header `X-Callback-Secret: <callbackSecret>`,
and (optionally) written to `RESULT_OUTPUT_PATH`:

```jsonc
{ "status": "completed", "dimensions": {…}, "data": { "temperature": [[[…]]], "velocity": [[[{x,y,z}]]], "pressure": [[[…]]] }, "logTail": ["…"] }
// or
{ "status": "failed", "errorMessage": "…", "logTail": ["…"] }
```

Temperature is converted Kelvin → Celsius to match the app's field envelope.

## Environment

| Var                  | Purpose                                             |
| -------------------- | --------------------------------------------------- |
| `CASE_INPUT_PATH`    | `gs://bucket/…/input.json` or a local path          |
| `RESULT_OUTPUT_PATH` | `gs://bucket/…/result.json` or a local path (opt.)  |
| `RUN_JOB_ID`         | Firestore run job id (echoed back)                  |
| `CALLBACK_URL`       | App callback endpoint (opt. for the local proof)    |
| `CALLBACK_SECRET`    | Shared secret sent as `X-Callback-Secret`           |

## Phase C1 — local proof (plan §4.1)

Prove the solver locally before touching the cloud. No GCS, no callback.

```bash
# 1. Build the image
docker build -t cfd-solver services/cfd-solver

# 2. Export one small real room to ./case-input/input.json via the debug script:
#    npx tsx scripts/ts/smoke-openfoam-export.ts --write ./case-input/input.json
#    (or any script that emits the input.json contract above)

# 3. Run the container with plain volume mounts
docker run --rm \
  -v "$PWD/case-input:/in" -v "$PWD/case-output:/out" \
  -e CASE_INPUT_PATH=/in/input.json \
  -e RESULT_OUTPUT_PATH=/out/result.json \
  cfd-solver

# Gate to pass: ./case-output/result.json contains non-NaN, physically plausible
# temperature/velocity/pressure arrays for that room.
```

Expected first-run failure modes are pre-analyzed in the plan (§4.1): degenerate
boundary faces (read the non-fatal `checkMesh` output in `logTail`), empty
`topoSet` faceSets, divergence before the first write interval (relax
`fvSolution`), and fluidfoam shape mismatch (the wrapper asserts the structured
mesh shape against `nx/ny/nz` and fails loudly).

## Phase C2 — cloud (plan §4.2)

```bash
# Artifact Registry + push
gcloud artifacts repositories create cfd --repository-format=docker --location=$REGION
docker tag cfd-solver $REGION-docker.pkg.dev/$PROJECT/cfd/cfd-solver:latest
docker push          $REGION-docker.pkg.dev/$PROJECT/cfd/cfd-solver:latest

# GCS exchange bucket with a 7-day lifecycle (inputs/outputs are transient)
gsutil mb -l $REGION gs://$BUCKET
gsutil lifecycle set lifecycle.json gs://$BUCKET   # age:7 → delete

# Cloud Run Job (tune after observing C1's real memory use)
gcloud run jobs create cfd-solver \
  --image $REGION-docker.pkg.dev/$PROJECT/cfd/cfd-solver:latest \
  --cpu 4 --memory 8Gi --task-timeout 3600 --max-retries 0 --region $REGION
```

Then set the app env (`CFD_GCS_BUCKET`, `CFD_CLOUD_RUN_JOB`, `CFD_CLOUD_RUN_REGION`,
`CFD_GCP_PROJECT`, `CFD_CALLBACK_SECRET`, `CFD_CALLBACK_BASE_URL`) — see
`src/lib/engine/simulation/cfd-cloud.ts`.
